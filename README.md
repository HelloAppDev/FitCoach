# FitCoach

iOS-приложение с ИИ-коучем по питанию и тренировкам. Все расчёты (калории, БЖУ, прогрессия весов) делает приложение, а языковая модель общается с пользователем и вызывает эти расчёты как инструменты.

Модель работает локально на Mac через [Ollama](https://ollama.com). Приложение подключается к ней по OpenAI-совместимому API (`/v1/chat/completions`).

## Требования

| | Минимум | Зачем |
|---|---|---|
| Mac | Apple Silicon (M1 и новее) | модель считается на видеочипе; на Intel работает, но медленно |
| Оперативная память | 8 ГБ, лучше 16 ГБ | модель занимает около 4 ГБ, плюс Xcode и Симулятор |
| Место на диске | около 5 ГБ | файл модели |
| Xcode | 16 или новее | в проекте минимальная версия iOS 18 |

## 1. Установка Ollama

Есть два способа, подойдёт любой.

**Через Homebrew.** Установить:

```bash
brew install ollama
```

И запустить Ollama в фоне (она будет стартовать вместе с Mac):

```bash
brew services start ollama
```

**Приложение.** Скачать Ollama с [ollama.com/download](https://ollama.com/download), перенести в «Программы» и запустить. В строке меню появится иконка ламы, значит сервер работает.

Проверить, что сервер запущен:

```bash
curl http://127.0.0.1:11434/v1/models
```

Должен прийти JSON вида `{"object":"list","data":[...]}`. Если в ответ пришло `Connection refused`, Ollama не запущена.

## 2. Скачивание модели

По умолчанию приложение использует `gemma3:4b` (около 3.3 ГБ):

```bash
ollama pull gemma3:4b
```

У `gemma3` нет поддержки вызова функций, поэтому с ней коуч отвечает только по данным из промпта, без инструментов. Чтобы коуч работал как агент (история упражнений, расчёт следующего веса), нужна модель с поддержкой инструментов, например:

```bash
ollama pull qwen2.5:7b
```

Подойдут и другие модели с пометкой `tools` в [каталоге Ollama](https://ollama.com/search?c=tools): `qwen3`, `llama3.1`, `llama3.2`, `mistral`. Приложение само определяет, умеет ли модель вызывать инструменты, и при необходимости работает без них.

## 3. Проверка модели

Список скачанных моделей:

```bash
ollama list
```

Короткий диалог прямо в терминале (выход — `/bye`):

```bash
ollama run gemma3:4b "Привет! Ответь одним предложением."
```

Проверка через тот же API, который использует приложение:

```bash
curl http://127.0.0.1:11434/v1/chat/completions -H "Content-Type: application/json" -d '{"model":"gemma3:4b","messages":[{"role":"user","content":"Привет!"}]}'
```

Первый ответ может идти 5–15 секунд, пока модель загружается в память. Следующие приходят быстрее. После ~5 минут без запросов Ollama выгружает модель из памяти, и следующий запрос снова будет медленнее.

Какие модели сейчас загружены в память:

```bash
ollama ps
```

## 4. Подключение в Симуляторе

Симулятор работает на том же Mac, поэтому адрес `127.0.0.1` в нём указывает на Ollama на этом же Mac. Дополнительно ничего настраивать не нужно.

В приложении: вкладка **«Тренер»** → шестерёнка:

- **Адрес:** `http://127.0.0.1:11434/v1` (стоит по умолчанию);
- **Модель:** точное название из `ollama list`, например `gemma3:4b` или `qwen2.5:7b`;
- **API-ключ:** оставить пустым.

Нажать **«Проверить связь»**. Должно появиться «Связь есть. Доступные модели: …».

## 5. Подключение на реальном iPhone

iPhone обращается к Ollama на Mac по Wi-Fi, поэтому нужно несколько дополнительных шагов.

### 5.1. Подпись приложения

В Xcode: проект **FitCoach** → target **FitCoach** → **Signing & Capabilities** → **Team**. Выбрать свой Apple ID (подойдёт бесплатный). Если Xcode пишет, что Bundle Identifier занят, поменять его на уникальный.

На iPhone включить **Режим разработчика**: Настройки → Конфиденциальность и безопасность → Режим разработчика.

### 5.2. Открыть Ollama для локальной сети

По умолчанию Ollama принимает запросы только с самого Mac. Чтобы она принимала их из сети, нужна переменная `OLLAMA_HOST=0.0.0.0`.

**Если Ollama установлена через Homebrew.** Остановить фоновый сервис:

```bash
brew services stop ollama
```

И запустить сервер, открытый для сети:

```bash
OLLAMA_HOST=0.0.0.0 ollama serve
```

Окно терминала нужно держать открытым, пока работает приложение.

**Если установлено приложение Ollama.** Задать переменную:

```bash
launchctl setenv OLLAMA_HOST 0.0.0.0
```

Затем закрыть Ollama через иконку в строке меню и запустить заново.

### 5.3. Узнать IP-адрес Mac

```bash
ipconfig getifaddr en0
```

Проверить, что Ollama доступна по этому адресу (подставить свой IP):

```bash
curl http://192.168.1.5:11434/v1/models
```

### 5.4. Настройка в приложении

1. iPhone и Mac должны быть в **одной Wi-Fi сети**.
2. В приложении: **«Тренер»** → шестерёнка → **Адрес** `http://<IP-адрес-Mac>:11434/v1`, например `http://192.168.1.5:11434/v1`.
3. При первом подключении iPhone попросит доступ к локальной сети. Нажать **«Разрешить»**. Если случайно запретили: Настройки → Конфиденциальность и безопасность → Локальная сеть → FitCoach.
4. Если на Mac включён файрвол, он может спросить, разрешить ли входящие подключения для `ollama`. Разрешить.
5. Нажать **«Проверить связь»**.

## Решение проблем

| Симптом | Причина и решение |
|---|---|
| Баннер «Нет связи с моделью», `Could not connect to the server` | Ollama не запущена. Проверить командой `curl http://127.0.0.1:11434/v1/models` |
| «Сервер вернул 404 … model not found» | Модель не скачана или её название в настройках написано иначе. Сверить с `ollama list` |
| Первый ответ очень долгий | Модель загружается в память, это нормально |
| Ответы медленные, Mac тормозит | Не хватает памяти. Закрыть лишние программы или взять модель меньше, например `qwen2.5:3b` |
| В Симуляторе работает, на iPhone нет | Ollama не открыта для сети (нет `OLLAMA_HOST=0.0.0.0`), в адресе указан `127.0.0.1` вместо IP Mac, устройства в разных сетях или не дан доступ к локальной сети |
| IP Mac изменился | Роутер выдаёт адреса динамически. Снова выполнить `ipconfig getifaddr en0` и обновить адрес в настройках |
