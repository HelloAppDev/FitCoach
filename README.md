# FitCoach

iOS-приложение с локальным двухмодельным ИИ-агентом по питанию и тренировкам.

- `qwen3:8b` анализирует запрос и составляет план действий агента.
- `gemma3:4b` формирует ответы пользователю и анализирует изображения.
- Swift-код выполняет точные расчёты и разрешённые действия на устройстве.
- EventKit добавляет будущие тренировки в системный календарь только после подтверждения пользователя.

Обе модели запускаются на Mac через [Ollama](https://ollama.com), а приложение подключается к OpenAI-совместимому API `/v1/chat/completions`.

## Требования

| Компонент | Минимум | Рекомендация |
|---|---|---|
| Mac | Apple Silicon M1 | M2 или новее |
| Оперативная память | 8 ГБ | 16 ГБ и больше |
| Место на диске | около 7 ГБ | 10 ГБ свободного места |
| Xcode | 16 | актуальная стабильная версия |
| iOS | 18 | реальный iPhone или Симулятор |

## 1. Установка Ollama

Через Homebrew:

```bash
brew install ollama
brew services start ollama
```

Либо скачать приложение с [ollama.com/download](https://ollama.com/download) и запустить его.

Проверка сервера:

```bash
curl http://127.0.0.1:11434/v1/models
```

Если получен `Connection refused`, Ollama не запущена.

## 2. Установка моделей

Приложению нужны обе фиксированные модели:

```bash
ollama pull gemma3:4b
ollama pull qwen3:8b
```

Проверить установку:

```bash
ollama list
```

Переключение моделей в интерфейсе отключено, потому что у них разные роли.

## 3. Архитектура ИИ-агента

Для каждого сообщения выполняется следующий цикл:

```text
Текст пользователя
        ↓
Qwen составляет JSON-план действий
        ↓
Приложение проверяет белый список инструментов и аргументы
        ↓
CoachTools выполняет безопасные чтения и расчёты
        ↓
При изменении календаря приложение запрашивает подтверждение
        ↓
Gemma получает контекст и результаты инструментов
        ↓
Gemma формирует итоговый ответ
```

Изображение передаётся только Gemma. Qwen получает текстовую отметку о наличии изображения, но не анализирует его.

### Инструменты агента

| Инструмент | Назначение | Изменяет устройство |
|---|---|---|
| `get_nutrition_status` | Возвращает нормы калорий, БЖУ, воды и остаток на сегодня | Нет |
| `suggest_next_load` | Рассчитывает следующую нагрузку через `TrainingEngine` | Нет |
| `get_exercise_history` | Возвращает историю конкретного упражнения | Нет |
| `create_calendar_event` | Подготавливает будущую тренировку для календаря | Только после подтверждения |

Qwen может выбрать максимум три действия за один запрос. Неизвестные инструменты отбрасываются. За один запрос разрешается подготовить только одно календарное событие.

Пример внутреннего плана:

```json
{
  "actions": [
    {
      "name": "create_calendar_event",
      "arguments": {
        "title": "Тренировка ног",
        "start_at": "2026-11-27T18:00:00+05:00",
        "duration_minutes": 60,
        "reminder_minutes": 30
      }
    }
  ]
}
```

## 4. Работа с календарём

Запрос пользователя может выглядеть так:

> Добавь тренировку ног в календарь на пятницу в 18:00 на один час.

Qwen преобразует относительную дату в ISO 8601 с часовым поясом устройства и вызывает `create_calendar_event`. Инструмент только подготавливает событие. В интерфейсе появляются кнопки **«Добавить»** и **«Отмена»**.

Только после нажатия **«Добавить»** приложение:

1. запрашивает write-only доступ к календарю;
2. выбирает системный календарь по умолчанию;
3. создаёт событие через `EKEventStore`;
4. при необходимости добавляет напоминание;
5. сообщает пользователю результат.

Приложение не читает существующие события календаря. В `Info.plist` используется `NSCalendarsWriteOnlyAccessUsageDescription`.

## 5. Анализ изображений

В чате есть кнопка выбора изображения из медиатеки. Перед отправкой изображение:

1. преобразуется в JPEG;
2. сжимается на устройстве;
3. кодируется в base64;
4. отправляется Gemma через OpenAI-совместимый формат `image_url`.

Можно приложить фотографию еды и спросить:

> Что изображено и как это вписывается в мой рацион?

Изображение используется только для текущего ответа и не сохраняется в истории модели. Числовые значения калорий по фотографии являются оценкой модели, поэтому точные БЖУ пользователь должен внести вручную.

## 6. Запуск в Симуляторе

Симулятор работает на том же Mac, поэтому адрес по умолчанию подходит:

```text
http://127.0.0.1:11434/v1
```

В приложении открыть **«Тренер» → шестерёнка** и нажать **«Проверить связь»**. Успешный результат:

```text
Связь есть. Gemma и Qwen готовы к работе.
```

Для проверки календаря у Симулятора должен существовать календарь по умолчанию. При первом добавлении iOS запросит write-only доступ.

## 7. Запуск на реальном iPhone

### 7.1. Подпись

В Xcode открыть target **FitCoach → Signing & Capabilities → Team** и выбрать Apple ID. На iPhone включить **Настройки → Конфиденциальность и безопасность → Режим разработчика**.

### 7.2. Открыть Ollama для локальной сети

Если Ollama запущена через Homebrew:

```bash
brew services stop ollama
OLLAMA_HOST=0.0.0.0 ollama serve
```

Если используется приложение Ollama:

```bash
launchctl setenv OLLAMA_HOST 0.0.0.0
```

После этого перезапустить Ollama.

### 7.3. Узнать IP Mac

```bash
ipconfig getifaddr en0
```

В настройках FitCoach указать адрес, например:

```text
http://192.168.1.5:11434/v1
```

iPhone и Mac должны находиться в одной Wi-Fi сети. При первом обращении нужно разрешить FitCoach доступ к локальной сети.

## 8. Проверка функций

### Расчёт питания

1. Добавить приём пищи.
2. Спросить: «Сколько калорий мне осталось сегодня?»
3. Qwen должен выбрать `get_nutrition_status`, а Gemma — объяснить точный результат.

### Следующая нагрузка

1. Добавить жим лёжа 70 кг на 8 повторов.
2. Спросить: «Какой вес поставить в следующий раз?»
3. Qwen должен выбрать `suggest_next_load`, а расчёт должен выполнить `TrainingEngine`.

### Календарь

1. Спросить: «Запланируй тренировку спины на завтра в 19:00».
2. Проверить название, дату и длительность в карточке подтверждения.
3. Нажать **«Добавить»**.
4. Разрешить доступ к календарю при первом запуске.
5. Проверить событие в системном приложении «Календарь».

### Изображение

1. Нажать кнопку с иконкой фотографии.
2. Выбрать изображение.
3. Добавить вопрос и отправить сообщение.
4. Ответ должна сформировать Gemma.

## Решение проблем

| Симптом | Причина и решение |
|---|---|
| `Could not connect to the server` | Ollama не запущена или указан неправильный IP |
| Не загружена Gemma | Выполнить `ollama pull gemma3:4b` |
| Не загружена Qwen | Выполнить `ollama pull qwen3:8b` |
| Qwen не смог составить план | Переформулировать запрос; убедиться, что установлена именно instruct-модель |
| Нет запроса доступа к календарю | Проверить разрешение FitCoach в настройках iOS; повторный запрос не показывается после отказа |
| Нет календаря для записи | Создать или включить календарь по умолчанию на устройстве/Симуляторе |
| В Симуляторе работает, на iPhone нет | Проверить `OLLAMA_HOST=0.0.0.0`, IP Mac, Wi-Fi, локальную сеть и файрвол |
| Первый ответ долгий | Ollama загружает модель в память; при смене Qwen/Gemma возможна дополнительная задержка |
| Mac тормозит | Закрыть лишние приложения; две модели могут поочерёдно загружаться в память |

## Основные файлы

| Файл | Ответственность |
|---|---|
| `AI/LocalLLMCoach.swift` | Маршрутизация Qwen/Gemma, история, планирование и выполнение агентного цикла |
| `AI/CoachTools.swift` | Белый список инструментов, проверка аргументов и подготовка календарного события |
| `AI/CoachContext.swift` | Профиль, питание, тренировки и системный промпт Gemma |
| `Services/CalendarService.swift` | Запрос разрешения и запись подтверждённого события через EventKit |
| `Engine/NutritionEngine.swift` | Расчёт калорий, БЖУ и воды |
| `Engine/TrainingEngine.swift` | План тренировок и прогрессия нагрузки |
